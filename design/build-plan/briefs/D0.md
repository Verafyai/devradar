   `git clone devradar-import.bundle devradar && cd devradar && git remote set-url origin <repo url> && git push -u origin main`.
   (With the tgz instead: unpack into the empty repo, commit as "Import DevRadar site as deployed (version 8538def)", push to main.)
   Keep the import commit unchanged so the history starts from what is live.
2. **Do not** reformat, minify, rename or "clean up" anything in the import. In particular, the ten large files in `api/`
   (`scan.js`, `report.js`, `cron.js`, `correct.js`, `overlay.js`, `datasets.js`, `github.js`, `unlock.js`, `buzz.js`, `health.js`,
   about 2 to 3 MB each) are prebuilt bundles of the Deep Scan backend. Their original sources are not in the import.
   Leave them byte for byte; note them in the README as vendored bundles. (Do not commit `.vercel/`, `.env*`, `.data/`, `node_modules/`.)

     `app_deep_scan`, `app_event_scanner`, `app_docs_scanner`, `app_competition`, `app_social_trends`, `app_developer_profiler`,
     `app_influencers`, `app_ideas`, `app_looper`, `seo_v2`, `copy_v2`. `DEVRADAR_FLAGS` env (comma list or `all`) turns flags on.
     Expose `isOn(name)` for server code and a way for static pages and `scripts/render-pages.mjs` to read the same flags
     (for example a generated `/flags.js` or build time rendering). Unit tests for the helper.
   - `README.md` additions: "Feature flags" (every new surface ships behind a flag; with no flags set the site renders as before;
     turning a flag on in production is Rex's call), "Vendored Deep Scan bundles", and "Deploy" (unchanged: the existing tarball
